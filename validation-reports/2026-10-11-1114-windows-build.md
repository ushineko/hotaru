### Phase 5: Security Review

- Dependencies: govulncheck v1.9.0, database of 2026-10-08. sanshoku moves
  to 0.1.14 and fynedesygn to 0.1.96; `golang.org/x/net` moves to 0.60.0
  with them.
  - hotaru's modules: 0 vulnerabilities.
  - Under this machine's Go 1.27.0: 13 in the Go standard library, all fixed
    in Go 1.27.2. 9 are in code hotaru calls (`net/http`, its HTTP/2,
    `net/textproto`, `crypto/tls`: GO-2026-6603, 6605, 6607, 6608, 6610,
    6611, 6612, 6613, 6617). 4 are not called (GO-2026-6599, 6600, 6604,
    6609).
  - Under Go 1.27.2 (`GOTOOLCHAIN=go1.27.2`): no vulnerabilities, for
    Windows with the window, and for Linux without it.
  - 2026-10-12: this machine's Go was updated to 1.27.2. With no toolchain
    override the scan finds no vulnerabilities, and the tests, the window's
    tests, `go vet` and the linter pass again.
  - These come from the Go a binary is built with, not from this change.
    hotaru's API listens on a socket only its user can open, which limits who
    can reach the HTTP ones. A binary for release should be built with Go
    1.27.2 or later, or a patched 1.26.
- Access control: the socket is the only way in. On Windows its access list
  is replaced with one entry for the current user and protected from
  inheritance. A test reads the list back. Nobody tried to connect as a
  second user.
- A window exists between listening and restricting, as on Linux between
  listening and `chmod`. The default directory is inside the user's profile.
- Injection, secrets, deserialisation: no new input, no credentials, no new
  format.
- The listener guard no longer reads test files. A test that opened a port
  would not be caught; the program's files are all still read.
- Status: PASSED.
